# Kipatik

Платформа управления разработкой программного обеспечения, объединяющая
доску задач, контроль версий и командное взаимодействие, с модулями
анализа кода: трассировкой коммитов к задачам, определением типа изменения
и оценкой прогресса.

## Требования

- Git
- Docker и Docker Compose
- Для запуска без Docker: Python 3.10+, Node.js 18+, PostgreSQL, Redis

## Запуск через Docker

Образ бэкенда собирается из корня репозитория: в него попадает и код, и
руководства из `docs/`.

1. Клонируйте репозиторий и подготовьте настройки:

   ```bash
   cp backend/.env.example backend/.env
   ```

   Задайте в `backend/.env` хотя бы `SECRET_KEY`. Всё остальное имеет
   рабочие значения по умолчанию.

2. Поднимите базу и Redis:

   ```bash
   docker compose up -d db redis
   ```

3. Примените миграции — **отдельной командой**:

   ```bash
   docker compose run --rm backend alembic upgrade head
   ```

   Миграции вынесены из `CMD` намеренно: схема применяется один раз при
   развёртывании, а не при каждом перезапуске контейнера. Иначе второй
   экземпляр приложения менял бы схему чужой базы.

4. Запустите сервер:

   ```bash
   docker compose up -d backend
   ```

5. Запустите фронтенд в отдельном терминале:

   ```bash
   cd frontend
   npm install
   npm run dev
   ```

## Рабочий режим

Запуск в режиме разработки описан выше. Когда приложение нужно открыть
пользователям, режим меняется — и менять его нужно в нескольких местах:

| Что | В разработке | В рабочем режиме |
|---|---|---|
| Сервер | `uvicorn app.main:app --reload` | `uvicorn app.main:app` без `--reload` |
| Интерфейс | `npm run dev`, порт 3000 | `npm run build` и раздача папки `frontend/dist` веб-сервером |
| Порт 8000 | Открыт наружу для отладки | Доступен только прокси |
| Кросс-доменные запросы | Разрешены отовсюду | Ограничены прокси |

Полный порядок развёртывания — раздел «Развёртывание» в
[руководстве администратора](docs/admin-guide.md): сборка образа,
миграции, раздача интерфейса, подключение артефактов моделей монтированием
и проверки после развёртывания.

## Запуск без Docker

**Сервер:**

```bash
cd backend
python -m venv venv
# Windows:  .\venv\Scripts\activate
# Linux/Mac: source venv/bin/activate

pip install -r requirements.txt

# PostgreSQL и Redis должны быть подняты
alembic upgrade head

uvicorn app.main:app --reload
```

**Клиент:**

```bash
cd frontend
npm install
npm run dev
```

В разработке клиент живёт на `http://localhost:3000` и обращается к
серверу через прокси из `vite.config.ts`. Отдельно запускать что-либо не
нужно.

## Первый вход

При первом старте, если в базе нет пользователя с идентификатором 1,
автоматически создаётся учётная запись:

| Поле | Значение |
| :--- | :--- |
| Email | `admin@example.com` |
| Пароль | `admin` |

Это значение по умолчанию, а не пароль. Смените его сразу после первого
входа.

> Переменные `FIRST_SUPERUSER` и `FIRST_SUPERUSER_PASSWORD`, которые
> встречаются в некоторых версиях этого файла, код не читает. Учётная
> запись создаётся с указанными выше значениями без настройки.

## Нейросетевые модели

Кодировщик трассировки, классификатор типов коммитов и модуль оценки
объёма включаются и выгружаются из памяти в панели администратора.
Артефакты весов в репозиторий не попадают: кодировщик весит около
гигабайта.

Артефакты обеих моделей лежат в одной папке `backend/app/ai/code_model`:

```
backend/app/ai/code_model/commit_tracer.pt
backend/app/ai/code_model/type_classifier.pt
backend/app/ai/code_model/paraphrase-multilingual-mpnet-base-v2/
backend/app/ai/code_model/progress_estimator.py
```

Все эти файлы лежат в репозитории: клонирование даёт готовый комплект.
Словарь можно восстановить отдельно командой
`python backend/scripts/fetch_tokenizer.py`, проверить наличие —
`python backend/scripts/fetch_tokenizer.py --check`.

Кодировщик весит около гигабайта, поэтому хранится через Git LFS. Перед
клонированием выполните один раз `git lfs install`, иначе файлы останутся
указателями и анализ кода не заработает — причина видна на странице
«Управление нейросетевыми моделями».

`torch` не входит в `backend/requirements.txt` намеренно: базовый образ
тянет десятки гигабайт вариантов CUDA. Для сборки образа с моделями
используйте `--build-arg INSTALL_TORCH=true`.

## Проверка

```bash
# Сервер: 13 наборов проверок по настоящей базе PostgreSQL
cd backend
.\venv\Scripts\python.exe -W ignore tests\run_all.py

# Клиент: логика фильтра задач
cd frontend
npm test
```

Перед началом работы с базой её нужно поднять: проверки читают и пишут
в неё по-настоящему.

## Ролевая модель

В каждом проекте у пользователя своя роль:

| Роль | Основные возможности |
| :--- | :--- |
| **Руководитель проекта** | Полный доступ. Настройки, Git, участники, роли, задачи, удаление проекта. |
| **Менеджер** | Всё, кроме удаления проекта. Приглашение участников (кроме руководителей), редактирование доски. |
| **Разработчик** | Задачи: создание, перемещение, правка **своих** задач, назначение себя. Код-ревью. |
| **Тестировщик** | Создание и перемещение задач, работа со **своими** задачами. Не может править задачи, не назначенные на него. |
| **Наблюдатель** | Только просмотр проекта, доски и задач. |

Права задаются на уровне ролей в панели администратора; состав ролей и
матрица прав описаны в [руководстве администратора](docs/admin-guide.md).
