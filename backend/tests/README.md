# Проверки

Тесты самодостаточны: каждый запускается обычным скриптом и печатает отчёт
с итогом вида `ИТОГ: N/N проверок пройдено`. pytest в проекте нет, и ставить
его ради этих файлов незачем.

## Запуск

Из папки `backend`, при поднятом PostgreSQL:

```powershell
.\venv\Scripts\python.exe -W ignore tests\run_all.py
```

Отдельный тест:

```powershell
.\venv\Scripts\python.exe -W ignore tests\test_enrichment.py
```

## Внимание

**Проверки работают по настоящей базе и по настоящим данным.**

- `test_cascade_delete.py` — работает в транзакции и откатывает её,
  но проверяет удаление на реальном PostgreSQL: SQLite внешние ключи
  по умолчанию не проверяет, и каскады там не воспроизводятся.
- `test_branch_default.py` — создаёт и удаляет репозитории в тестовом URL.
- `test_users_endpoints.py` — создаёт пользователя через эндпоинт и
  удаляет его сам.
- `test_suggestion_confirm.py` — создаёт коммит и предложение, удаляет сам.
- `test_suggestions_filter.py` — заводит репозиторий-зонд и удаляет всё по его
  `id`, поэтому чужие предложения не затрагиваются.
- `test_progress_volume.py` — заводит **собственную задачу-зонд**: у задач
  проекта уже есть связи, и проверять на них нельзя, результат зависел бы от
  того, что нажали до нас.
- `test_task_type.py` — создаёт задачи с названием «Зонд типа задачи…» и
  удаляет их по `LIKE`.
- `test_enrichment.py` — **ходит в GitLab по токену пользователя, у которого
  есть доступ к тестовому репозиторию**. Синхронизация, правки и разбор
  моделью занимают около 25 секунд.

На боевой установке не запускать.

## Что проверяется

| Файл | Что |
|---|---|
| `test_cascade_delete.py` | Удаление проекта не падает с `ForeignKeyViolationError` и уносит приглашения, репозитории с коммитами и правками, уведомления, вложения, комментарии. Также: ссылки на `users` не каскадят. |
| `test_branch_default.py` | `default_branch` доходит от мастера подключения до базы. Раньше поля не было в схеме запроса, Pydantic его отбрасывал, и репозиторий уезжал в `main`. |
| `test_startup.py` | Приложение поднимается целиком: `TestClient` входит в контекстный менеджер, поэтому выполняется lifespan со всеми событиями старта. Остальные наборы этого не делают и потому не видят ошибок только в стартовом коде — так уже проскочило падение сервера из-за вызова переименованной функции реестра моделей. Здесь же проверяется, что стартовый код ссылается на существующие имена, что интервал фоновой сверки берётся из настроек, и что диагностика моделей отвечает после старта. |
| `test_task_search.py` | Поиск задач из строки в шапке: пустой и короткий запрос дают пустой список, поиск по названию находит задачу, в ответе заполнено название проекта, выдача не выходит за пределы проектов, где пользователь участник, `limit` работает и срезан сверху. Отдельно — что маршрут `/search` объявлен раньше `/{task_id}` и не перехватывает карточку задачи. |
| `test_docs_serving.py` | Руководства лежат в `docs/` — по два на русском и английском — и отдаются сервером по `/manuals/<файл>`; отдаётся ровно тот файл, что лежит в репозитории, а не устаревшая копия. Проверяется, что `/docs` остался за встроенной документацией API, что при `SERVE_DOCS=false` текст не отдаётся, и что монтирование не сломало корень, Swagger, поиск задач и сборку схемы OpenAPI. Режим раздачи задаётся переменной окружения, поэтому набор запускается дважды — с `true` и с `false`. |
| `test_repo_files.py` | Целостность файлов поставки без обращения к базе. Правила игнорирования проверяются через `git check-ignore` во временном репозитории: миграции Alembic, код, инструкции, Dockerfile и образец настроек **не** исключаются, а секреты, виртуальные окружения, веса моделей и загруженные файлы — исключаются. Отдельно: папка словаря кодировщика обязана быть в репозитории, без неё модель не запускается. Проверяется Dockerfile (нет `--reload`, есть непривилегированный пользователь, миграции не навешаны на `CMD`), compose (контекст сборки — корень, ожидание готовности базы, тома), образец настроек (каждая переменная реально читается, секреты пустые) и качество инструкций — всех четырёх, включая английские: таблицы не разорваны, нет имён файлов исходников, нет незакрытых заглушек, язык файла соответствует его имени. |
| `test_users_endpoints.py` | Регистрация и выдача пользователей не падают с `MissingGreenlet`: связь `git_accounts` грузится заранее, а не лениво на сериализации. |
| `test_suggestion_confirm.py` | «Принять» сохраняет связь и **сразу** считает тип коммита; «Скрыть» убирает её из `task_commits`. |
| `test_suggestions_filter.py` | Выдача предложений ограничена задачей и репозиторием. Раньше `/git/{id}/suggestions` возвращал предложения всего проекта, и в карточке задачи показывались чужие — в том числе из другого репозитория, из-за чего переключатель репозитория ничего не менял. Заодно проверяется, что задача чужого проекта не открывается по номеру. |
| `test_progress_volume.py` | `additions`/`deletions` считаются по тексту правки, когда провайдер их не прислал. Плюс сама формула прогресса: семантика множитель, а не слагаемое (одна строка кода больше не даёт 50%), штраф за чужие файлы ограничен половиной, отсутствие упомянутых файлов не наказывается, подзадачи остаются ведущей составляющей. Отдельно — стягивание калибровки объёма к априорному значению при малой выборке и проверка, что неподтверждённые предложения в прогресс не попадают. |
| `test_admin_storage.py` | Управление хранилищем: настройки читаются и меняются через панель; значения вне границ отклоняются, не портя загрузку; расширения нормализуются; очистка по сроку трогает только просроченное, а полная — всё; файлы удаляются с диска, а не только из базы; освобождённое место возвращается счётчику проекта; проект без своего лимита показывает общий; обычному пользователю панель закрыта. |
| `test_admin_models.py` | Управление моделями администратором: решение действует поверх флага окружения и переживает перечитывание кеша; классификатор типов нельзя включить при выключенном кодировщике; выключенный классификатор не поднимает кодировщик, то есть отключение действительно освобождает память; обычному пользователю панель закрыта. |
| `test_user_search.py` | Поиск пользователей для приглашения в проект отвечает 200 и находит людей по имени и почте, в ответе заполнены вложенные `git_accounts`, неактивные не показываются. Раньше эндпоинт падал в 500, как только поиск хоть кого-то находил, — окно приглашений показывало пустоту, а ошибка уходила в консоль. |
| `test_project_background.py` | Фон страницы проекта: новый проект без фона, базовый включается обновлением, а вид `custom` через обновление поставить нельзя (иначе был бы битый фон без файла). Загрузка кладёт картинку на диск и включает свой фон, некартинка и пустой файл отвергаются, повторная загрузка убирает прежний файл, снятие фона и уход на базовый удаляют файл. |
| `test_rejected_link.py` | Отклонение помечает связь, а не удаляет: модель не предлагает тот же коммит заново, отказ виден в выборе объектов, ручная привязка превращает его в подтверждение, отказ обратим. Отклонённое не попадает ни в карточку задачи, ни в прогресс. Цикл «скрыть → вернуть» не теряет единицу в счётчике на вкладке «Разработка». |
| `test_task_type.py` | Тип задачи доходит от запроса до базы, меняется, очищается; опечатка отклоняется с 422 и не меняет значение, а пустая строка означает «без типа». Раньше тип был заглушкой по чётности id. |
| `test_enrichment.py` | После синхронизации фоновая доработка доводит репозиторий до `done`: правки подтягиваются, модель предлагает привязки. Если репозиторий по этому URL уже подключён, он **не трогается вовсе**, а связи снимаются снимком и возвращаются в конце — раньше тест стирал подтверждённые связи пользователя. |

## Добавление проверки

1. Файл `tests/test_что-то.py`, шапка — предупреждение о настоящих данных.
2. Функция `check(name, cond, extra)` пишет строку в `results`.
3. В конце печатается `ИТОГ: N/N проверок пройдено` — его и разбирает `run_all.py`.
4. Убрать за собой: всё, что создано в БД, удалить в `finally`.
5. Добавить файл в `TESTS` в `run_all.py`.

Формат итоговой строки жёсткий: `ИТОГ: (\d+)/(\d+) проверок пройдено`.
