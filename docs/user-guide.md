# Руководство пользователя Kipatik

Kipatik — веб-система для управления разработкой программных проектов. В ней ведётся доска задач, обсуждаются задачи в комментариях, хранится история изменений и автоматически подтягиваются коммиты и Pull Request из Git-репозитория.

Руководство предназначено для участников проектов: разработчиков, тестировщиков, менеджеров и руководителей проектов. Оно описывает интерфейс целиком: от входа в систему до работы с Git-интеграцией.

## Как читать руководство

Названия кнопок, полей и разделов приведены в «кавычках» ровно так, как они выглядят в интерфейсе. Действия описаны короткими шагами.

### Условные обозначения

| Обозначение | Значение |
|---|---|
| Полоса слева на карточке: красная, янтарная, синяя | высокий, средний, низкий приоритет |
| Бейдж типа задачи: Исправление, Новая функциональность, Рефакторинг, Документация, Тестирование, Сопровождение | тип задачи; задаётся вручную, а для коммитов определяется моделью |
| Бейдж «вручную» | связь с коммитом, веткой или Pull Request подтверждена человеком |
| Бейдж «модель» | связь предложена моделью по смыслу изменений |
| Бейдж «авто» | связь найдена автоматически, например по номеру задачи в тексте коммита |
| Число рядом с бейджем «модель» или «авто» | уверенность системы в связи, в процентах |
| ⚠ рядом с уверенностью | уверенность низкая, связь стоит проверить |
| Звёздочка `*` у поля | поле обязательно по правилам проекта |
| `+N` рядом с аватарами | участников больше, чем показано значками |
| `99+` и `9+` в счётчиках | счётчик обрезан |
| Проценты рядом с оценками модели | насколько система уверена в выводе; это не гарантия точности |
| Приглушённый бейдж типа коммита | модель неуверенно определила этот тип |

## 1. Начало работы

### 1.1 Вход в систему

1. Откройте адрес системы в браузере — появится страница «Вход в Kipatik».
2. Введите «Имя пользователя или email».
3. Введите «Пароль». Значок глаза слева от поля показывает пароль открытым текстом и снова скрывает его.
4. Нажмите «Войти».

После входа открывается «Главная» со списком ваших проектов. Если сессия сохранена, при следующем открытии системы вход происходит автоматически.

Выйти из системы можно значком выхода справа в верхней панели.

### 1.2 Регистрация аккаунта

1. На странице «Вход в Kipatik» нажмите «Создать аккаунт» в нижнем блоке.
2. Заполните «Полное имя», «Email» и «Пароль».
3. Пароль должен содержать от 8 до 72 символов.
4. Нажмите «Зарегистрироваться».

После регистрации выполняется автоматический вход. Если аккаунт уже есть, вернитесь к входу по ссылке «Войти».

### 1.3 Язык интерфейса и размер текста

Обе настройки находятся в профиле.

| Настройка | Значения | Как применяется |
|---|---|---|
| Язык интерфейса | English, Русский | Меняется сразу после выбора и сохраняется в профиле; при следующем входе подхватывается автоматически |
| Размер текста | от 13 до 20 пикселей, по умолчанию 16 | Кнопки «−», «+» и «Сбросить», рядом предпросмотр; сохраняется в браузере и действует во всех разделах |

### 1.4 Защищённые и незащищённые разделы

| Раздел | Доступ |
|---|---|
| Вход, Создание аккаунта | Без входа |
| Главная, доска проекта, карточка задачи, профиль, история | Только после входа |
| Админ. панель | Только для пользователей с правами администратора |

В верхней панели слева показаны хлебные крошки: «Kipatik», затем «Главная» (или «Админ. панель» для администратора), затем название текущего проекта.

## 2. Главная страница

Главная состоит из трёх панелей: «Ваши проекты», «Ваши задачи» и «Уведомления».

**«Ваши проекты»** — карточки всех проектов, участником которых вы являетесь. Над карточками есть поле поиска по названию. Если проектов нет, показан экран «Добро пожаловать в Kipatik» с кнопкой «Создать первый проект».

**«Ваши задачи»** — задачи, назначенные вам, по всем проектам.

| Элемент | Назначение |
|---|---|
| Поле поиска над списком | Фильтр по заголовку и описанию |
| Список «Сортировка» | Дедлайн, Приоритет, Статус, Новые |
| Карточка задачи | Открывает карточку задачи в её проекте |

**«Уведомления»** — полный список уведомлений. В шапке панели показан счётчик непрочитанных; при количестве больше 99 выводится «99+».

**Сворачивание панелей.** В шапке каждой панели есть шеврон — «Свернуть панель» и «Развернуть панель». Свернутая панель превращается в узкую полосу. Одновременно свёрнута не более одной панели: если свернуть другую, ранее свёрнутая развернётся.

**Изменение ширины панели проектов.**

1. Наведите курсор на вертикальный разделитель между панелями «Ваши проекты» и «Ваши задачи».
2. Зажмите левую кнопку мыши и потяните разделитель вправо или влево.
3. Отпустите кнопку.

Ширина занимает от 20 до 60 процентов окна и запоминается для этого браузера.

## 3. Проекты

### 3.1 Создание проекта

Кнопка доступна только пользователям, которым разрешено создавать проекты.

1. На главной странице нажмите плитку «Создать новый проект» или значок «+» в шапке панели «Ваши проекты».
2. В окне «Новый проект» заполните «Название проекта».
3. При желании заполните «Описание».
4. Нажмите «Создать проект».

Сразу после создания открывается мастер подключения репозитория — см. раздел 6.2.

### 3.2 Карточка проекта на главной

Карточка показывает название и описание (без описания выводится «Описание отсутствует»), владельца с пометкой «(Вы)», вашу роль, имя подключённого репозитория, до трёх аватаров участников с «+N» при большем количестве и общий счётчик участников, а также бейдж провайдера: GitHub, GitLab, Bitbucket или Git. Клик по карточке открывает доску проекта.

### 3.3 Участники и приглашения

1. Откройте проект и нажмите «Участники» в шапке.
2. В окне «Участники» есть вкладки «Участники проекта» и «Приглашение». Вкладка «Приглашение» доступна ролям «Рук. проекта» и «Менеджер».

**«Участники проекта»** показывает аватар, имя и роль каждого участника, свою строку помечает «(Вы)». Значок корзины на строке удаляет участника после подтверждения. Удалить себя и владельца проекта нельзя — кнопка для них скрыта.

**«Приглашение»**:

1. Введите в поле поиска имя или email — не менее двух символов. Уже приглашённые, действующие участники и вы сами в выдаче не показываются.
2. Выберите роль будущего участника в списке «Роль для приглашения».
3. Нажмите «Пригласить» у найденного пользователя — появится подтверждение «Приглашение отправлено пользователю <email>».
4. Список «Ожидают принятия» показывает отправленные, но не принятые приглашения со статусом «Ожидание…».

Роль «Рук. проекта» доступна только тем, кто уже имеет её: менеджер назначить её не может. Окно закрывается кнопкой внизу.

### 3.4 Роли участников и что кому доступно

В проекте пять ролей.

| Возможность | Рук. проекта | Менеджер | Разработчик | Тестировщик | Наблюдатель |
|---|---|---|---|---|---|
| Просмотр проекта, доски и задач | да | да | да | да | да |
| Создание задач | да | да | да | да | нет |
| Редактирование задач | да | да | только свои задачи | только назначенные на него | нет |
| Удаление задач | да | да | только свои задачи | нет | нет |
| Перемещение задач между колонками | да | да | да | да | нет |
| Назначение исполнителя | да | да | только на задачах, где он уже исполнитель | нет | нет |
| Приоритет, сроки, подзадачи | да | да | в своих задачах | в назначенных задачах | нет |
| Приглашение участников и роли | да | да | нет | нет | нет |
| Удаление участника из проекта | да | да, но не участника с ролью «Рук. проекта» | нет | нет | нет |
| Правила проекта | да | да | нет | нет | нет |
| Настройки проекта, Git-подключение, вебхуки | да | да | нет | нет | нет |
| Создание ветки из задачи | да | да | если он исполнитель задачи | нет | нет |
| Комментарии | да | да | да | да | нет |
| Удаление любого комментария | да | да | только свои | только свои | нет |
| Pull Request: просмотр, комментарий, одобрение | да | да | да | да | только просмотр |
| Удаление проекта | только владелец проекта или администратор | нет | нет | нет | нет |

Дополнительно: право создавать проекты выдаётся отдельно и не зависит от роли в проекте; администратор, не являющийся участником проекта, получает права «Рук. проекта» автоматически.

### 3.5 Фон проекта

Фон настраивается в «Настройках проекта», вкладка «Общее», раздел «Фон страницы».

| Вариант | Что происходит |
|---|---|
| Без фона | Фон убирается, страница остаётся белой |
| Базовый | Применяется фон из поставки системы |
| Свой | Открывается выбор файла; принимаются только PNG и JPEG |

Фон применяется сразу, отдельная кнопка «Сохранить» не требуется. Подсказка предупреждает: фон виден всем участникам проекта, а меняет его тот же человек, который меняет название проекта. «Выбрать файл» заменяет фон, «Убрать фон» удаляет его. Пока фон сохраняется, выводится «Сохраняем фон…», при ошибке — «Не удалось изменить фон».

### 3.6 Удаление проекта

Удалить проект может только владелец проекта или администратор.

1. Откройте «Настройки» в шапке проекта и перейдите на вкладку «Общее».
2. Нажмите «Удалить проект».
3. Подтвердите удаление в предупреждении о том, что действие нельзя отменить и все задачи и файлы будут удалены.

Остальным участникам вместо настроек показывается предупреждение «Только владелец проекта может изменять эти настройки».

## 4. Доска проекта

### 4.1 Шапка проекта

| Элемент | Назначение |
|---|---|
| Название проекта | Клик по названию или значок карандаша — переименование. Доступно владельцу проекта и администратору |
| «Фильтр» | Панель фильтра задач; рядом — число активных фильтров |
| «Правила проекта» | Настройка правил. Кнопка доступна ролям «Рук. проекта» и «Менеджер» |
| «Участники» | Окно участников и приглашений |
| «Настройки» | Окно настроек проекта: общее, Git, непривязанные события |
| «Сменить проект» | Возврат к списку проектов |
| «Новая задача» | Окно создания задачи |

При переименовании нажмите Enter, чтобы сохранить, или Esc, чтобы отменить; пустое название сохранить нельзя. Кнопка «Новая задача» неактивна, пока в проекте нет ни одной колонки. Над каждой группой колонок показан счётчик задач, видимых после фильтра.

В правилах проекта доступны:

- «Обязательные поля при создании» — Описание, Срок выполнения, Исполнитель, Приоритет. Такие поля помечаются звёздочкой в окне создания задачи.
- «Автоматическое назначение исполнителя» — при переносе задачи в другую колонку исполнителем становится текущий пользователь.
- «Логика даты начала выполнения» — один из вариантов: «Совпадает с датой создания», «Задается руководителем/менеджером», «Задается исполнителем».
- «Ограничения по колонкам для ролей» — для каждой колонки выбираются роли, которым разрешено перемещать в неё задачи.
- «Пользовательские SQL-правила» — поле с SQL-запросом. «Проверить» показывает «Запрос корректен» или «Ошибка в запросе»; «Добавить правило» появляется только после успешной проверки. Сохранённые правила перечислены в списке и могут быть удалены.

Нажмите «Сохранить», чтобы применить правила.

### 4.2 Пять представлений

Под шапкой проекта расположены вкладки представлений; активная выделяется цветной линией снизу.

| Вкладка | Что показывает |
|---|---|
| Доска | Канбан с колонками и карточками задач |
| Список | Таблица задач с сортировкой и поиском |
| Карта | Временная шкала: полосы задач по месяцам |
| Граф | Схема зависимостей между задачами |
| История | Лента активности проекта |

**Список.** В панели инструментов есть поиск по заголовку и описанию. Клик по заголовкам столбцов «Заголовок», «Статус», «Приоритет», «Срок выполнения» переключает сортировку по возрастанию и убыванию. В строке видны номер задачи, заголовок, описание, статус, приоритет, срок, исполнитель, счётчики подзадач и комментариев. Клик по строке открывает карточку задачи.

**Карта.** Шкала показывает три месяца от выбранной даты, с сеткой дней и подсветкой выходных.

- Стрелка ‹ сдвигает окно на месяц назад, стрелка › — на месяц вперёд.
- Кнопка между стрелками возвращает к текущему месяцу.
- Полосы задач окрашены по группе колонки и подписаны номером задачи справа; клик по полосе открывает задачу.
- Если полос не видно, выводится подсказка «Установите даты начала или завершения, чтобы увидеть задачи на дорожной карте». Задачи без отдельной даты начала используют дату создания.

**Граф.** Узлы — задачи, линии — зависимости между ними. Цвет узла соответствует приоритету, подписи появляются при увеличении.

- «Добавить зависимость» запускает режим привязки: сначала выберите задачу, которая будет зависеть от другой, затем задачу, от которой она зависит.
- «Отмена» в шапке графа выключает режим привязки; клик по узлу открывает карточку задачи.
- Панель «Статистика» показывает количество задач по приоритетам и всего.

**История.** Лента активности проекта: задачи и Git-события, до 100 записей. Подробно — в разделе 8.

### 4.3 Колонки: добавить, переименовать, удалить

Колонки объединены в три группы: `TODO`, `IN PROGRESS`, `DONE`. Внутри группы колонки идут по порядку.

**Добавить:** нажмите значок «+» в шапке нужной группы, введите «Название» в окне «Добавить колонку», проверьте подсказку «Будет добавлена в состояние …» и сохраните.

**Переименовать:** наведите курсор на заголовок колонки, нажмите значок карандаша, измените «Название» в окне «Изменить колонку» и сохраните.

**Удалить:** наведите курсор на заголовок колонки, нажмите значок корзины и подтвердите удаление в вопросе «Вы уверены, что хотите удалить эту колонку? Задачи останутся в проекте».

### 4.4 Перетаскивание задач между колонками

1. Нажмите карточку задачи и, удерживая кнопку мыши, перетащите её в другую колонку.
2. Во время перетаскивания рядом с курсором видна полупрозрачная копия карточки.
3. Отпустите кнопку — задача сразу получит статус новой колонки.

Карточку можно переносить и без мыши: выберите её с клавиатуры и переместите стрелками. Если в проекте включено «Автоматическое назначение исполнителя», при переносе задачи исполнителем станет текущий пользователь.

### 4.5 Фильтр задач

1. Нажмите «Фильтр» в шапке проекта.
2. Выберите условия в панели «Фильтр задач»:

| Условие | Значения |
|---|---|
| Исполнитель | Участники проекта и пункт «Любой» |
| Приоритет | Низкий, Средний, Высокий |
| Тип | Шесть типов задачи цветными бейджами |
| Просроченные | Только задачи с истёкшим сроком выполнения |

3. Строка «Показано X из Y» показывает, сколько задач осталось.
4. Кнопка «Сбросить» снимает все условия.

Фильтр действует одинаково во всех представлениях — «Доска», «Список», «Карта» и «Граф», и применяется сразу по уже загруженным задачам проекта.

### 4.6 Поиск задач в шапке приложения

Поле «Поиск задач...» в верхней панели ищет по всем вашим проектам.

1. Введите не менее двух символов в поле «Поиск задач...».
2. В выдаче появятся задачи с названием задачи и проекта.
3. Нажмите на результат — откроется карточка задачи в нужном проекте.

Enter открывает первый результат, Esc и клик вне поля закрывают выдачу. При отсутствии результатов выводится «Ничего не найдено», при сбое — «Не удалось выполнить поиск». На узких экранах поле скрыто.

## 5. Задачи

### 5.1 Создание задачи

Создать задачу можно кнопкой «Новая задача» в шапке проекта или кнопкой «+ Добавить задачу» внизу нужной колонки — колонка будет предвыбрана.

1. Введите «Заголовок» — это единственное поле, обязательное всегда.
2. При необходимости заполните «Описание», «Дата начала» и «Срок выполнения».
3. Выберите «Тип» и «Приоритет».
4. При необходимости добавьте подзадачи в «Чек-лист».
5. По желанию нажмите «Анализ ИИ» — см. раздел 7.1.
6. Нажмите «Добавить задачу».

Поля, помеченные звёздочкой, обязательны по правилам проекта: если такое поле не заполнено, задача не создаётся и система сообщает об этом. Для отмены есть «Отмена».

### 5.2 Поля задачи

| Поле | Где задаётся |
|---|---|
| Заголовок | Окно создания, затем шапка карточки задачи |
| Описание | Окно создания, вкладка «Общее» |
| Статус (колонка) | Боковая панель карточки, перетаскиванием на доске |
| Тип | Боковая панель, окно создания: Без типа, Исправление, Новая функциональность, Рефакторинг, Документация, Тестирование, Сопровождение |
| Приоритет | Боковая панель, окно создания: Низкий, Средний, Высокий |
| Дата начала и Срок выполнения | Боковая панель, окно создания |
| Исполнитель | Боковая панель, окно создания: Не назначен или участник проекта |
| Подзадачи | «Чек-лист» в окне создания, чек-лист во вкладке «Общее» |
| Зависимости | Раздел «Зависимости» во вкладке «Общее», вкладка «Граф» |
| Комментарии и вложения | Вкладка «Обсуждение» |
| Ветки, коммиты, Pull Request | Вкладка «Разработка» |
| «Создано» и «Дата начала» (исторические) | Вкладка «Общее», только чтение |

### 5.3 Карточка задачи: вкладка «Общее»

Карточка открывается кликом по карточке на доске, по строке в списке, по полосе на карте, по узлу графа, по результату глобального поиска или по ссылке «Задача #N →» в истории.

В шапке карточки заголовок можно править прямо в поле — текст сохраняется, когда поле теряет фокус; значок ✕ закрывает карточку. Вкладки: «Общее», «Обсуждение» (со счётчиком комментариев), «Разработка» (со счётчиком коммитов и веток), «История».

Во вкладке «Общее» редактируется «Описание» — так же, по уходу фокуса; ниже показаны «Создано» и «Дата начала» только для чтения, затем чек-лист подзадач со счётчиком «выполнено X из Y».

Боковая панель доступна во всех вкладках:

| Поле | Как менять |
|---|---|
| Статус | Выберите колонку из выпадающего списка |
| Тип | Нажмите на нужный тип; у выбранного стоит галочка |
| Приоритет | Нажмите на «Низкий», «Средний» или «Высокий» |
| Дата начала, Срок выполнения | Укажите дату и время |
| Исполнитель | Выберите «Не назначен» или участника проекта |

Когда задачу назначают другому человеку, ему приходит уведомление.

### 5.4 Подзадачи

**Добавить:** вкладка «Общее» → поле «Добавить подзадачу...» → кнопка «+».

**Отметить выполненной:** поставьте галочку в чекбоксе рядом с подзадачей. Счётчик «выполнено X из Y» и полоса прогресса обновятся; на карточке задачи на доске появится полоса прогресса по подзадачам.

**Удалить:** наведите курсор на строку подзадачи и нажмите значок корзины.

При создании задачи подзадачи добавляются в «Чек-лист» окна создания, где корзина удаляет строку до создания задачи.

### 5.5 Зависимости между задачами

**Добавить:** вкладка «Общее» → раздел «Зависимости» → «Добавить зависимость» → введите название задачи или её номер с решёткой, например `#42` → выберите найденную задачу.

**Удалить:** наведите курсор на строку зависимости и нажмите значок корзины.

Если зависимостей нет, выводится «Зависимости не указаны». Зависимости видны на вкладке «Граф» в виде линии между задачами; там их можно добавить, выбрав сначала зависимую задачу, затем задачу, от которой она зависит.

### 5.6 Вкладка «Обсуждение»

**Комментарий.** Введите текст в поле внизу, при необходимости приложите файлы и нажмите «Комментировать». Комментарии обновляются автоматически каждые пять секунд, пока вкладка открыта, и лента сама прокручивается к последнему сообщению.

**Ответ на комментарий.**

1. Наведите курсор на комментарий и нажмите «Ответить».
2. В поле ввода появится цитата с именем автора и началом текста.
3. Напишите ответ и нажмите «Комментировать». Значок ✕ в блоке цитаты отменяет ответ.

**Реакции.** Наведите курсор на комментарий, нажмите значок смайлика и выберите реакцию: 👍 ✅ 👀 🚀 ❤️ 🔥 😂 😮. Реакции показываются под комментарием со счётчиками, собственные подсвечены; повторный выбор той же реакции снимает её.

**Вложения.** Значок скрепки в поле ввода загружает файл; ✕ на чипе убирает неотправленное вложение; клик по чипу в опубликованном комментарии скачивает файл; ✕ на чипе в форме редактирования снимает вложение при правке.

Ограничения: не более 5 файлов в одном сообщении; файл больше 25 МБ отклоняется на клиенте с сообщением «Файл слишком большой (макс. 25МБ)»; сервер дополнительно проверяет размер, расширение и лимит хранилища проекта — см. раздел 11.

**Правка и удаление.** Меню «⋯» на комментарии открывает «Редактировать» и «Удалить». При редактировании можно одновременно снять вложения. Удалить комментарий может его автор либо пользователь с ролью «Рук. проекта» или «Менеджер».

**Форматирование текста.** Блок кода — тройные обратные кавычки; код в строке — одинарные обратные кавычки; **жирный** — две звёздочки; *курсив* — одна; ***оба*** — три; ссылка — `[текст](адрес)`; упоминание — `@` и имя или email без пробелов; ссылка на коммит — `#commit ` и короткий идентификатор, выводится бейджем.

Упоминания вводятся вручную: подсказка со списком сотрудников не появляется. Упомянутый человек получает уведомление.

### 5.7 Вкладка «Разработка»

**Шапка вкладки:** название подключённого репозитория и состояние подключения (если интеграция не настроена — «Git-интеграция не настроена»), выбор репозитория, если их несколько, кнопка «Обновить» и кнопка «Создать ветку».

«Создать ветку» создаёт в репозитории ветку `feature/task-<номер задачи>-<фрагмент заголовка>` и автоматически переводит задачу в группу `IN PROGRESS`. Кнопка доступна ролям «Рук. проекта», «Менеджер» и исполнителю задачи.

**Блок «Прогресс»** стоит первым; подробно — в разделе 7.2. Если коммитов нет, выводится «Оценка пока невозможна: к задаче не привязан ни один коммит».

**Раздел «Предложения (N)»** — предложения модели трассировки, см. раздел 7.4; у каждого есть «Принять» и «Скрыть».

**Раздел «Ветка»** — список веток с бейджем источника связи: «вручную», «модель» или «авто».

**Раздел «Pull Request»** — для каждого запроса показаны номер и название со ссылкой на провайдера, статус (открыт, слит, закрыт), ветки источника и назначения, сводка `+N −M`, число изменённых файлов, состояние проверок CI («CI пройден», «CI упал», «CI выполняется») со ссылкой на прогон и список ревьюеров с решениями; у ещё не ответивших — «ждём».

**Раздел «Отклонённые (N)»** — свёрнутый список отклонённых привязок, см. раздел 6.8.

**Раздел «Коммиты (N)»** — список с коротким идентификатором, текстом, сводкой `+N −M`, бейджем типа коммита с процентом уверенности и бейджем источника связи. Раскройте строку коммита, чтобы увидеть полный текст, автора, дату, ссылку на коммит у провайдера, отметку «Подтверждено пользователем <имя>», строку «Тип по смыслу изменений: <тип> · N%» (и пометку «тип неуверенный», если тип ненадёжен) и список изменённых файлов с иконками: добавлен, удалён, переименован, изменён; сводкой `+N/−M` и для переименованных — «← предыдущий путь».

**Раздел «Изменённые файлы (N)»** — свёрнутый список всех файлов, затронутых по задаче.

**Привязка и отвязка.** «Перепривязать» открывает окно «Привязать объект к задаче», где у каждого коммита или Pull Request есть кнопка «Привязать». Значок «🔗×» на строке коммита, ветки или Pull Request отвязывает объект после подтверждения «Отвязать этот объект от задачи?». Если ничего не связано, выводится «С этой задачей пока не связано ни ветки, ни PR, ни коммитов» и кнопка «Перепривязать».

### 5.8 Вкладка «История» задачи

Показывает единую ленту: события самой задачи и связанные с ней объекты Git — ветки, коммиты, Pull Request. Фильтры и группировка по дням такие же, как в истории проекта: участник, тип события, «Только Git-события», «Сбросить фильтры», метки «Сегодня» и «Вчера».

### 5.9 Удаление задачи

1. Откройте карточку задачи.
2. В боковой панели нажмите «Удалить задачу».
3. Подтвердите удаление в вопросе «Вы уверены, что хотите удалить эту задачу?».

Карточка закроется, задача исчезнет из представлений проекта, а событие появится в истории.

## 6. Работа с Git

### 6.1 Подключение аккаунта провайдера

Аккаунт провайдера подключается в профиле, в правой колонке «Привязанные аккаунты». Поддерживаются GitHub, GitLab, Bitbucket и Gitea.

**Вход через провайдера**

1. Откройте профиль и в блоке нужного провайдера нажмите «Войти через <провайдер>».
2. Подтвердите доступ на странице провайдера.
3. Вернитесь в систему — аккаунт будет привязан.

Кнопка появляется только если OAuth-приложение настроено на сервере; при отказе, устаревшей ссылке или несовпадении провайдера система сообщает о причине.

**Вставка токена**

1. Нажмите «Вставить токен» в блоке провайдера.
2. Для GitHub введите имя пользователя и токен, для остальных провайдеров — только токен.
3. Сохраните.

| Провайдер | Что нужен |
|---|---|
| GitHub | Personal Access Token (classic) с правами `repo` и `workflow` |
| GitLab | Personal Access Token с правами `api` и `read_repository` |
| Bitbucket | Пароль приложения (App Password) с доступом к репозиторию |
| Gitea | Access Token в настройках Gitea |

**Отключение:** в блоке подключённого провайдера нажмите «Отключить» и подтвердите действие.

### 6.2 Подключение репозитория к проекту

Мастер подключения состоит из трёх шагов.

**Шаг 1 — Провайдер**

1. Выберите провайдера: GitHub, GitLab, GitLab (self-hosted), Gitea или Bitbucket.
2. Для self-hosted укажите «Адрес сервера (self-hosted)».
3. Укажите «Токен доступа». Если аккаунт уже подключён в профиле, поле необязательно — токен подставится сам.
4. Нажмите «Проверить»: при успехе выводится «Токен рабочий. Аккаунт: <имя>».
5. Нажмите «Далее».

**Шаг 2 — Репозиторий**

1. Введите «URL репозитория».
2. Укажите «Ветка по умолчанию» — по умолчанию `main`.
3. При необходимости заполните «Фильтр по путям» — для монорепозиториев перечислите через запятую префиксы путей; пустое поле означает, что репозиторий не фильтруется.
4. Нажмите «Подключить».

**Шаг 3 — Вебхук**

Мастер показывает чек-лист «Секрет подписи сгенерирован» и «Вебхук зарегистрирован у провайдера». Если регистрация удалась, появляется плашка «Интеграция готова». Подробности — в разделе 6.5. Кнопка «Готово» закрывает мастер.

### 6.3 Несколько репозиториев в одном проекте

1. Откройте «Настройки» → вкладка «Git».
2. Нажмите «Добавить ещё репозиторий» и пройдите мастер.

В списке «Подключённые репозитории» выберите активный репозиторий — тот, данные которого показываются по умолчанию; рядом показан индикатор ошибки или успеха синхронизации. Если репозиториев несколько, нужный выбирается и на вкладке «Разработка» карточки задачи.

### 6.4 Синхронизация и проверка подключения

**Синхронизация**

1. Откройте «Настройки» → вкладка «Git» и нажмите «Синхронизировать».

Блок «Синхронизация» показывает ветку по умолчанию, время последней синхронизации («ни разу», если её ещё не было), состояние (Успешно, Ошибка, Не выполнялась) и состояние разбора (Идёт разбор, Готово, Ошибка разбора, Не выполнялся). Если разбор не завершился, выводится сообщение о загруженных коммитах и о том, что разбор продолжается; предложения появятся в карточках задач позже — обновите вкладку «Разработка». Помимо ручной, система периодически обновляет подключённые репозитории сама.

**Проверка подключения**

1. В том же блоке нажмите значок проверки «↻».

Результат — четыре отметки: «Репозиторий найден» (система видит репозиторий у провайдера), «Секрет подписи настроен» (секрет совпадает с настройками на стороне провайдера), «Тестовое событие получено» (события действительно приходят), «Подпись верифицирована» (подпись последнего события корректна). Дополнительно показываются время последнего события и время последней верифицированной подписи.

### 6.5 Вебхуки

Вебхук — механизм, через который провайдер сообщает системе о новых коммитах и Pull Request.

**Автоматическая регистрация.** Если провайдер её поддерживает, на шаге 3 мастера доступна кнопка «Зарегистрировать автоматически», а после успеха — плашка «Интеграция готова».

**Ручная настройка.** Для провайдеров без авторегистрации выводится предупреждение «Этот провайдер не поддерживает авторегистрацию».

1. Скопируйте «URL вебхука» и «Секрет» кнопками «Скопировать».
2. В настройках Webhooks вашего репозитория у провайдера добавьте вебхук с этими данными.
3. Ориентируйтесь на подсказку «События: push, pull request (merge request)».

URL и кнопка копирования есть и в «Настройках» → «Git», там же доступна кнопка «Перевыпустить секрет» — после перевыпуска секрет нужно обновить у провайдера.

### 6.6 Сопоставление авторов коммитов

Чтобы в задачах и истории отображался автор коммита, сопоставьте его с пользователем системы.

1. Откройте «Настройки» → вкладка «Git».
2. Нажмите «Сопоставить авторов коммитов».

| Элемент окна | Назначение |
|---|---|
| «Атрибуция коммитов» с полосой прогресса | Сколько коммитов сопоставлено: «X / Y (Z%)» |
| Счётчики «Авторов», «Не опознано», «Автоматом» | Общая картина по репозиторию |
| Фильтры «Все», «Не опознанные», «Сопоставленные» | Ограничение списка авторов |
| Поле поиска по автору | Фильтрация списка |
| «Пересопоставить» | Повторный автоматический подбор соответствий |
| «Обновить» | Перечитать список |
| «Сопоставить ▾» у автора | Ручной выбор пользователя из кандидатов |

Сначала коммиты сопоставляются по email, затем по логину провайдера. Если разработчик использует личную почту или другой логин, задайте соответствие вручную; у сопоставленного автора показывается бейдж «авто» или «сохранено». Если авторов нет, выводится «Авторов не найдено. Выполните синхронизацию репозитория». Пока часть коммитов не сопоставлена, вверху окна висит предупреждение, что их авторство не будет отображаться в задачах и истории.

### 6.7 Как коммит попадает в задачу

Есть три способа, их можно использовать одновременно.

| Способ | Как работает | Что делать пользователю |
|---|---|---|
| Автоматически по номеру | Если в тексте коммита есть ссылка вида `#15`, коммит привязывается к задаче №15 | Указывайте номер задачи в тексте коммита |
| По смыслу, моделью | Модель сопоставляет смысл изменений коммита с текстами задач и предлагает связь | Открыть «Предложения» на вкладке «Разработка» и решить: «Принять» или «Скрыть» |
| Вручную | Привязка любого коммита или Pull Request из окна «Привязать объект к задаче», а также из «Непривязанные события» | Открыть «Перепривязать» или вкладку «Непривязанные события» |

У любого связанного объекта показан бейдж источника: «вручную», «модель» или «авто».

### 6.8 Отклонённые связи и возврат их к рассмотрению

1. Откройте вкладку «Разработка» и раскройте раздел «Отклонённые (N)» — там видны короткий идентификатор и текст коммита.
2. Нажмите «Вернуть» у нужной связи. Появится сообщение «Предложение возвращено к рассмотрению», и предложение снова попадёт в раздел «Предложения».

### 6.9 Создание ветки из задачи

1. Откройте карточку задачи и перейдите на вкладку «Разработка».
2. Нажмите «Создать ветку».

Будет создана ветка `feature/task-<номер задачи>-<фрагмент заголовка>`, а задача автоматически перейдёт в группу `IN PROGRESS`. Кнопка доступна ролям «Рук. проекта», «Менеджер» и исполнителю задачи.

### 6.10 Непривязанные события

1. Откройте «Настройки» → вкладка «Непривязанные события»; в заголовке вкладки показан счётчик.
2. Для каждого события указаны тип (`push` или `pull_request`), короткий идентификатор, время и текст коммита либо название Pull Request.
3. Введите номер задачи в поле `Task #ID` и нажмите «Link».

Если непривязанных событий нет, выводится «All Git events are linked!».

## 7. Автоматический анализ (ИИ)

### 7.1 Анализ задачи при создании

1. Откройте окно создания задачи.
2. Заполните «Заголовок» и, по возможности, «Описание».
3. Нажмите «Анализ ИИ». Кнопка активна, только если заполнен заголовок; во время анализа показывает «Анализирую...».
4. Система выдаст рекомендацию: плашка «Рекомендуемый приоритет: Высокий» или «Рекомендуемый приоритет: Обычный».
5. Проверьте результат: приоритет в форме уже подставлен, при необходимости выберите другой вручную.

Рекомендация не отменяет правила проекта: если приоритет помечен звёздочкой и не заполнен, задача всё равно не создастся.

### 7.2 Оценка прогресса

Блок «Прогресс» стоит первым на вкладке «Разработка» карточки задачи и появляется, когда к задаче привязан хотя бы один коммит.

| Элемент | Содержание |
|---|---|
| Полоса прогресса и процент | Расчётная оценка готовности |
| Метка уверенности | «уверенность высокая», «уверенность средняя» или «уверенность низкая» |
| «Почему такой процент?» | Подзадачи (X/Y), Объём (изменено строк из ожидаемых), Прицельность (сколько названных в описании файлов затронуто) |
| «Что ограничивает точность» | Причины: нет привязанных коммитов, нет подзадач, в описании не упомянуты файлы, мало данных для калибровки |
| Пояснение источника ожидаемого объёма | Откуда взято число строк: по проекту, по системе или значение по умолчанию |
| «Динамика по дням» | График накопления объёма по дням |

При простое без коммитов не менее четырёх дней появляется «Нет коммитов уже N дн.». Если коммитов нет вообще, выводится «Оценка пока невозможна: к задаче не привязан ни один коммит».

### 7.3 Определение типа коммита

Тип коммита определяется по смыслу изменений и показывается бейджем в списке коммитов.

| Что видно | Как читать |
|---|---|
| Бейдж типа с процентом | Тип определён моделью; рядом указана уверенность в процентах |
| Приглушённый бейдж | Этот класс модель на примерах определяет ненадёжно — не ориентируйтесь на него |
| Пометка «тип неуверенный» | Дублирует предупреждение о ненадёжном классе |
| «Тип определён моделью и проверен на примерах» | Класс в выборке проверок определяется устойчиво |

При ненадёжном определении рядом появляется пояснение «Тип определён моделью, но этот класс на примерах определяется ненадёжно».

### 7.4 Предложения связей «коммит → задача»

1. Откройте вкладку «Разработка» карточки задачи и раздел «Предложения (N)».
2. В каждом предложении указаны короткий идентификатор коммита, текст коммита, уверенность в процентах и подпись «Возможно, относится к задаче: <название>».
3. Нажмите «Принять» — связь станет постоянной, появится «Связь подтверждена».
4. Нажмите «Скрыть» — предложение уйдёт в «Отклонённые», появится «Предложение скрыто».

Предложения появляются после синхронизации репозитория и обновляются при следующих синхронизациях.

### 7.5 Что остаётся на человеке

| Модель делает | Человек решает |
|---|---|
| Сопоставляет смысл изменений коммита с текстами задач и предлагает привязку | Принимать или скрывать каждое предложение |
| Определяет тип коммита по смыслу изменений | Считать ли этот тип верным, особенно при приглушённом бейдже |
| Рекомендует приоритет при создании задачи | Оставить рекомендованный приоритет или задать свой |
| Считает процент прогресса по подзадачам, объёму и прицельности | Считать ли оценку отражением реального состояния работы |

Правила работы с автоматическими выводами:

1. У каждого вывода есть уверенность в процентах. Низкая уверенность — сигнал проверить результат вручную.
2. При неуверенном типе бейдж типа приглушён, а рядом появляется пометка «тип неуверенный».
3. Модель лишь предлагает: ни одна привязка, ни один тип и ни одна оценка не применяются к задаче без решения человека.
4. Точность выводов не гарантируется: проценты уверенности — индикатор, а не оценка качества вашей работы.

## 8. История и активность

Лента доступна в двух местах: вкладка «История» на доске проекта и вкладка «История» в карточке задачи. В карточке к событиям добавляются связанные объекты Git — ветки, коммиты и Pull Request.

**Что попадает в ленту**

| Группа типов | События |
|---|---|
| Создание | Задача создана |
| Статус | Статус изменён: <из> → <в> |
| Исполнитель | Исполнитель изменён: <из> → <в> |
| Приоритет | Приоритет изменён: <из> → <в> |
| Комментарии | Добавлен комментарий |
| Подзадачи | Подзадача добавлена, отмечена как выполненная или невыполненная, удалена |
| Вложения | Файл загружен, файл удалён |
| Git | Отправка в репозиторий, Pull Request, создание и удаление ветки, Git-событие |

**Фильтры ленты**

| Фильтр | Значения |
|---|---|
| Участник | Все участники или конкретный участник |
| Тип | Все типы или одна из групп: Создание, Статус, Исполнитель, Приоритет, Комментарии, Подзадачи, Вложения, Git |
| Только Git-события | Только события типа Git |
| Сбросить фильтры | Снимает все условия |

Строка «Показано X из Y» показывает количество отфильтрованных событий; если по условиям ничего нет, выводится «По выбранным фильтрам ничего не найдено».

**Чтение ленты.** События сгруппированы по дням с метками «Сегодня», «Вчера» и датой. Событие со ссылкой «Задача #N →» открывает карточку задачи. Внутри события об отправке в репозиторий коммиты раскрываются: показаны первые три, остальные — под подписью «и ещё N». Значок «↻» рядом с заголовком обновляет ленту. Лента проекта показывает до 100 последних событий.

## 9. Профиль

Откройте профиль, нажав на блок с именем, email и аватаром в правой части верхней панели.

**Левая колонка — основные данные.** В поле «Имя» меняется имя, в «Email» — адрес (он должен быть уникальным в системе). Аватар загружается значком фотоаппарата либо задаётся адресом картинки в поле «URL аватара». Для фотографии: не более 5 МБ, форматы PNG, JPEG, GIF, WebP; кнопка «Убрать фотографию» удаляет её. Результат виден вверху формы: «Профиль успешно обновлен!», «Файл больше 5 МБ…», «Не удалось загрузить фотографию», «Не удалось убрать фотографию».

**Настройки отображения.** «Язык интерфейса» — English или Русский, применяется сразу и сохраняется в профиле. «Размер текста» — кнопки «−», «+», «Сбросить», предпросмотр, диапазон 13–20 пикселей.

**Привязанные аккаунты** — GitHub, GitLab, Bitbucket, Gitea, см. раздел 6.1.

Внизу левой колонки есть подсказка с иконкой щита: «Ваш email используется для связи коммитов и уведомлений». Именно по email и логину система сопоставляет авторов коммитов с пользователями. Нажмите «Сохранить», чтобы применить изменения.

## 10. Уведомления

Значок колокольчика справа от поиска показывает число непрочитанных уведомлений; при количестве больше 9 выводится «9+».

1. Нажмите колокольчик — откроется список последних семи уведомлений.
2. «Прочитать все» отмечает весь список прочитанным.
3. «Показать все» открывает панель «Уведомления» на главной странице.
4. Клик по уведомлению или кнопка под ним отмечают его прочитанным.

Уведомления появляются без перезагрузки страницы; если браузер разрешил системные уведомления, вы получите и сообщение ОС. Рядом с каждым уведомлением показано относительное время, например «2 минуты назад».

**Что приходит в уведомлениях**

| Событие | Что видите |
|---|---|
| Приглашение в проект | «Приглашение в проект» и роль, на которую вас пригласили |
| Ваше приглашение приняли | «Приглашение принято» у пригласившего |
| Ваше приглашение отклонили | «Приглашение отклонено» у пригласившего |
| Вас назначили исполнителем | «Вы были назначены исполнителем задачи: <название>» |
| Вас упомянули в комментарии | «<автор> упомянул вас в задаче #<номер>» |

Символ слева от текста зависит от типа: приглашение, назначение задачи, упоминание или информационное сообщение.

**Приглашение в проект.** Откройте колокольчик или панель «Уведомления» на главной странице и нажмите «Принять» — вы станете участником проекта, либо «Отклонить» — пригласившему придёт уведомление. Кнопки показываются только у непрочитанных приглашений.

Отдельных настроек уведомлений в системе нет: отключить определённые типы или указать адрес доставки нельзя.

## 11. Администрирование хранилища и лимиты (то, что видит пользователь)

Хранилище — это загруженные в систему файлы: вложения в комментариях, фотографии профилей и фоны проектов. Лимиты задаёт администратор; ниже — то, что касается вас как пользователя.

**Загрузка файла в комментарий.** Больше 5 файлов в одном сообщении отклоняется с сообщением «Максимум 5 файлов в одном сообщении». Файл больше 25 МБ пропускается с сообщением «Файл слишком большой (макс. 25МБ)». Недопустимое расширение и превышение лимита хранилища проекта отклоняются сервером с сообщением об ошибке. По умолчанию сервер принимает расширения `.png`, `.jpg`, `.jpeg`, `.gif`, `.pdf`, `.doc`, `.docx`, `.txt`, `.zip`, `.log`; администратор может изменить список.

**Лимит проекта.** У каждого проекта есть свой объём хранилища, а если индивидуальный лимит не задан, действует общий; по умолчанию общий лимит — 500 МБ на проект. Когда лимит исчерпан, новые файлы перестают загружаться, но задачи, комментарии и Git-интеграция продолжают работать.

**Почему удалённый файл ещё числится в корзине.** Удаление вложения не стирает файл с диска: запись переходит в корзину, и место освобождается только после её очистки. По умолчанию срок хранения в корзине — 7 дней, автоматическая очистка включена и выполняется по расписанию. Практический вывод: после удаления крупных вложений объём проекта какое-то время остаётся прежним; если лимит не хватает сразу, сообщите об этом администратору — он может очистить корзину принудительно.

**Фон проекта и фотография профиля.** Фон проекта — только PNG и JPEG, размер ограничен общим лимитом файла. Фотография профиля — не более 5 МБ, форматы PNG, JPEG, GIF, WebP.

## 12. Известные ограничения текущей сборки

Ниже — то, что в текущей версии заявлено в интерфейсе, но не работает или работает не полностью. Это ограничения сборки, а не инструкции.

| Ограничение | Что происходит сейчас | Что делать |
|---|---|---|
| Смена роли участника | В окне «Участники» есть выбор роли, но изменение не сохраняется | Обратиться к администратору проекта |
| «Взять задачу» на себя | В карточке задачи нет кнопки назначения себя исполнителем | Попросить руководителя или менеджера назначить вас |
| Кнопка «Фильтр» в представлении «Список» | Кнопка нарисована, но ничего не делает | Пользоваться «Фильтр» в шапке проекта — он работает и для списка |
| Подсказки при упоминании `@` | Список кандидатов не появляется | Вводить `@` вручную: email или имя без пробелов |
| «Забыли пароль?» | Ссылка на странице входа никуда не ведёт | Обратиться к администратору для сброса пароля |
| Возврат к списку проектов | Кнопка «На главную» на экране «Проект не выбран» и возврат после удаления проекта ведут не туда, куда ожидается | Открывать список проектов ссылкой «Главная» в верхней панели |
| Рекомендации «Анализа ИИ» | Подставляется только приоритет; тип задачи и подзадачи не подставляются | Задавать тип и подзадачи вручную |
| Метки и теги | В задачах нет ни меток, ни тегов | Пользоваться типом задачи, подзадачами и фильтром по типу |
| Фильтр по дате начала и исполнитель на карте | Такого фильтра нет; задачи без даты начала используют дату создания, исполнитель на карте не показывается | Смотреть даты и исполнителя во вкладке «Общее» или в представлении «Список» |
| Разбор после синхронизации | Разбор может идти долго, а его итог виден только после обновления страницы | Дождаться статуса «Готово» и нажать «Обновить» на вкладке «Разработка» |
| Уведомления о запросе ревью Pull Request | Такие уведомления не создаются | Следить за задачей и лентой истории |

## 13. Частые вопросы

### Забыл пароль, что делать?

Восстановления пароля в системе нет: ссылка «Забыли пароль?» на странице входа не работает. Обратитесь к администратору — он установит новый пароль.

### Куда делся мой коммит?

1. Откройте «Настройки» → «Git» → «Проверка подключения». Если нет отметки «Тестовое событие получено», события от провайдера не приходят.
2. Нажмите «Синхронизировать» и дождитесь статуса «Готово».
3. Откройте вкладку «Непривязанные события» — возможно, коммит там.
4. Проверьте вкладку «Разработка» нужной задачи, раздел «Отклонённые» — возможно, предложение скрыли ранее.
5. Убедитесь, что в тексте коммита указан номер задачи вида `#15`, если коммит должен привязаться автоматически.

### Почему у задачи нет оценки прогресса?

Оценка появляется, только когда к задаче привязан хотя бы один коммит. Сообщение «Оценка пока невозможна: к задаче не привязан ни один коммит» означает ровно это. Привяжите коммиты на вкладке «Разработка».

### Модель предложила привязать не тот коммит

Нажмите «Скрыть» в разделе «Предложения» — связь попадёт в «Отклонённые» и больше не будет предлагаться. Проверьте процент уверенности и действительно ли изменения в коммите относятся к задаче.

### Как вернуть скрытое предложение?

Откройте «Разработка» → раздел «Отклонённые (N)» → «Вернуть». Предложение вернётся в «Предложения».

### Почему фильтр ничего не показывает?

Строка «Показано X из Y» в панели фильтра показывает результат. Частые причины: задачи скрыты комбинацией условий, например «Просроченные» и конкретный исполнитель; в проекте нет задач с выбранным типом; задачи не загружены — фильтр работает по уже загруженным данным. Нажмите «Сбросить» и проверьте счётчик.

### Как переименовать проект?

Нажмите на название проекта в шапке доски или на значок карандаша, введите новое название и нажмите Enter либо кнопку сохранения. Переименование доступно владельцу проекта и администратору.

### Как перейти в другой проект?

Нажмите «Сменить проект» в шапке — откроется главная страница со списком проектов. Также работают ссылка «Главная» в хлебных крошках верхней панели и клик по логотипу «Kipatik».

### Куда исчезло удалённое вложение?

Файл переходит в корзину и учитывается в объёме проекта до её очистки. По умолчанию корзина очищается автоматически через 7 дней. Если место нужно освободить срочно, обратитесь к администратору.

### Кто может удалить проект?

Только владелец проекта и администратор. Роль «Менеджер» удалить проект не может.

### Почему не нажимается кнопка «Новая задача»?

В проекте нет ни одной колонки. Добавьте колонку через значок «+» в шапке одной из групп: `TODO`, `IN PROGRESS` или `DONE`.

### Как изменить язык или размер шрифта?

Откройте профиль кликом по своему имени в верхней панели. В разделе «Ваш профиль» выберите «Язык интерфейса» или измените «Размер текста» кнопками «−» и «+». Изменения применяются сразу.
